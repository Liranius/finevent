# 新闻与日历关联

已部署并完成本批验收：迁移、重启、三个只读接口及 65 分钟采集/资源观察通过，双端关联显示与双向跳转按用户反馈通过。首版采用人工核对：从新闻详情按日期范围、标题或基金代码查找已有日程，查看原文并填写关联依据后确认；日历详情反向展示相关报道。不会根据同日、同类或相似标题自动建立关联，不调用模型、不填入指标数值，也不改变日程、关注或提醒。

## 版本与证据

每条关联保存确认时的新闻和日程快照、人工依据及确认时间。读取时并列使用当前记录；任一版本变化（包括改期、取消、标题或正文修订）都会标为“待重新核对”，原关联不会自动撤销或重新确认。用户在新闻详情核对当前版本后可重新确认，或二次确认解除；重新确认替换该关联的确认快照，不提供独立的关联操作历史。

确认和解除在同一 SQLite 事务中检查关联修订号；确认还检查新闻和日程版本。旧设备的提交返回 409，不能覆盖后续确认。每次确认使用新的、不会复用的修订号；移除后再添加也不会接受旧操作。新闻、日历和原有修订表结构不变；新增 `news_calendar_links` 表，旧程序回退时忽略此表，再升级保留记录。

一条报道最多关联 20 项日程。普通新闻按现有 90 天规则清理时，其关联和确认快照随之清理，日历本身保留；AI 的独立一年证据保留不受影响。关联代表用户判断，不能证明来源独立核实、报道完整覆盖或事件影响方向。

## 接口

路径前缀 `/finevent/api/v1/`，均需登录，响应 `no-store`；写入沿用同源校验。

| 方法与路径                             | 内容                                                                                  |
| -------------------------------------- | ------------------------------------------------------------------------------------- |
| GET `calendar-link-search`             | `from`、`to` 为北京时间民用日期范围，`q` 为标题或基金代码包含查询，最多 100 字        |
| GET `news/{id}/calendar-links`         | 该报道的已确认关联，包含当前记录、确认快照、依据、时间和 `changed`                    |
| GET `calendar/{id}/news-links`         | 日程的关联报道，按确认修订号倒序，每页 30 条；`next` 原样作为下次 `before`            |
| PUT `news/{id}/calendar-links/{event}` | 确认或重新确认；传入 `revision`、`news_version`、`event_version`、`note`（5–1000 字） |
| DELETE 同上                            | 解除关联；传入当前 `revision`                                                         |

首次确认的 `revision` 为 0；后续操作使用读取结果的关联 `id`。不存在或新闻已清理返回 404，版本冲突返回 409，非法输入返回 400。搜索沿用日历日期范围校验，按区间重叠查询；只返回前 30 项并用 `more` 标明截断，须缩小条件，不能据此认定只有这些日程。分钟精度按北京时间日期查询，仅日期值不作 UTC 偏移。

查找默认取来源发布时间前后七天；发布时间未知则明确标为以今天为查找中心，不补造发布时间。该范围可以修改，只用于搜索。两个工作区之间跳转保留本次登录中的已应用/未提交新闻筛选及日历月份、视图和所选日期，不写入离线缓存；页面重载或重新登录后不保留。列表可见时每 30 秒读取关联；编辑、解除确认或已加载更多记录时暂停自动刷新，保留输入、错误与阅读位置，手动刷新可回到第一页。

## 验证与发布

Go 回归覆盖确认、双向查询、版本冲突、快照、重新确认、解除、重启、分页、清理、日期精度与鉴权。Chromium 在桌面和 393 px 窄屏实际操作查找、空结果、核对、键盘焦点、双向跳转、筛选保留、修订提示、冲突输入保留和失败重试；浏览器新闻/关联使用测试夹具，真实事务与存储由 Go 测试覆盖。

沿用 `scripts/publish-news.ps1` 的备份、失败回滚、服务重启及约 65 分钟观察。新报告增加 `calendar_links_required`，检查迁移/重启后的关联内容、快照、修订号及三个只读 API；旧签收报告不追加新要求。验证脚本不会创建业务关联、改关注或主动调用模型。发布初检完成前暂缓编辑关联，初检后再做真实新闻与日程的双端确认/查看验收；本地通过不代替该项。进度和其余限制见 [实施状态](implementation-status.md)。
