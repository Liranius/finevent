# 以报道和财经日历组织阅读，配置与记录集中到设置

## 决定与缘由

用户打开应用最常做的是读报道，其次是查日程。原来按采集、推送、AI 和验证等技术模块分入口，读一篇报道时会遇到许多只在配置或排障时才需要的操作。维护者确认采用「报道、财经日历、设置」三个一级入口，默认打开报道列表，桌面用顶栏，手机用底栏。

## 入口归属

属于当前报道或日程的动作留在详情，包括打开原文、触发和查看单篇 AI 解读、关注单条日程。跨条目生效的偏好、来源状态、预算、历史和开发者功能从设置进入。历史记录也是独立的查询任务，因此报道通知、日历提醒和 AI 解读记录在各自分类中各有入口，可以直接查看或重试。

原先把管理面板留在阅读页下方的做法能就近呈现所有技术能力，但会拉长阅读路径。集中设置之后，读者从详情返回时需要找回原报道及筛选，管理者从设置子页返回时需要找回原入口。两种路径分别用桌面键盘和窄屏触控核查。页面归属和展示细节以 `DESIGN.md` 为准。
