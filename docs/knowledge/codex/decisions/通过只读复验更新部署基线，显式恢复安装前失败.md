# 通过只读复验更新部署基线，显式恢复安装前失败

首次真实 Actions 部署在安装前被固化证据的七天有效期拦截。资源记录也只保留七天，旧报告到当前的连续历史已经无法完整证明。用户批准新增只读基线复验，以及针对确定未进入安装的失败操作的显式恢复流程。

原固化报告与托管文件状态继续作为静态配置依据，新操作观察当前容器、服务、配置、资源和正常采集，并生成独立报告。新报告明确说明保留期之前的历史缺口，覆盖新的观察窗口及之后；它不把不可恢复的旧历史标为通过。发布者审核后显式指定报告 ID 和摘要，部署继续检查证据时效、窗口结束后的连续资源历史、原有资源及前序验收条件。

没有选择修改旧报告时间、直接延长有效期、删除失败登记或重跑固化安装。只读复验需要等待至少两轮正常采集，增加部署前置时间，但不会为了取得新时间戳而变更生产配置。它仍受原容器与文件身份约束；容器重建或配置改变不属于这个入口的授权范围。

安装前失败恢复必须指定最新失败操作及其报告摘要，同时重新审核该操作原来的已完成前序。登记与工作进程均检查失败停在 preflight、观察进程已停止且没有安装、回滚或观察替换证据。旧失败记录保留，新操作有独立身份。安装结果不明和 AI 凭据准备失败仍需单独处理，不能借此入口重试。

## Observations

- [decision] 用户明确批准只读基线复验与安装前失败的显式恢复。
- [constraint] 新基线不重建缺失历史，原失败报告不可改写为成功。
- [constraint] 证据 ID 与摘要绑定到新操作，重复同一操作仍只查询原状态。
