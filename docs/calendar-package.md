# 导入已核对的日历数据包

首次安装按常规步骤创建配置。服务以 `-collect` 启动后，自行创建数据库并同步官方来源。需要离线初始化或补充已核对的年表时，从维护者取得独立 ZIP 和对应的 SHA-256。确认整包摘要后，以服务账户指向同一个持久数据目录执行：

```sh
sha256sum finevent-calendar-YYYYMMDD.zip
finevent -data /path/to/data -import-calendar-package finevent-calendar-YYYYMMDD.zip
```

命令在一个 SQLite 事务中校验并导入，完成后退出。日程、原文、核对记录和修订保存在该实例中，重启、升级和从数据库备份恢复都无需原 ZIP。重复导入沿用快照和事件 ID。统计局原文仅补缺，已被更新的主源覆盖时跳过。BLS 年表及劳工部公告按项目与统计期归并，改期追加修订并沿用关注。导入不会清除主源错误或计为主源同步成功。BLS 官方 ICS 仍在「设置 → 日历官方来源」预览并确认。

## 制作与维护

ZIP 根目录放置 UTF-8 的 `manifest.json` 和其中引用的文件。清单使用 `version: 1` 和有序的 `snapshots` 数组。每项包含以下字段。可参考[测试清单](../apps/server/internal/calendar/testdata/manifest.json)了解结构。

| 字段                          | 含义                                                                 |
| ----------------------------- | -------------------------------------------------------------------- |
| `source`、`file`              | `nbs` 或 `bls`，以及 ZIP 根目录中的正文文件名                        |
| `url`、`year`、`entries`      | 官方发布页或 PDF URL、发布年份和解析后的条数                         |
| `retrieved_at`、`reviewed_at` | 采集与人工核对时间，使用 Unix 秒                                     |
| `sha256`、`id`                | 正文原始字节的 SHA-256 小写十六进制；ID 由来源标识与摘要前 12 位连接 |
| `format`                      | BLS 年表和劳工部摘录填 `release-table`；统计局原始 HTML 省略此字段   |

统计局 ID 使用 `nbs-YYYY-摘要`，保留未经改写的官方 HTML。核对年份、覆盖条目和特殊时刻。BLS 年表使用 `bls-YYYY-摘要`，劳工部就业报告使用 `bls-notice-MMDDYYYY-摘要`。对照官方月清单、年表或报告，按美国东部日期、当地时刻、项目名、统计期填写 TSV，表头为 `date_et`、`time_et`、`release`、`reference_period`。清单按年表、后续公告的顺序排列。正文发生变化时重新核对并发布新的包和摘要。应用限制每份正文 2 MiB，每包最多 32 份正文，整包及解压后正文合计各不超过 16 MiB。

部署验收会将冻结备份里的事件 ID、已有修订和关注与升级后的实例比较，允许同步产生新修订。统计局主源不可用时，验收核对数据库里保存的原文摘要、导入时的核对凭据和仍有效的覆盖日期。兼容旧版已核对的统计局快照。新库缺少有效快照且主源仍失败时，来源验收标为待核查。
