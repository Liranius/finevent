# 日历与基金录入接口

所有接口位于 `/finevent/api/v1/`，使用既有单用户会话；写入需同源 Origin。响应不缓存，Service Worker 不缓存 API。

| 方法与路径                                   | 用途                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `GET calendar?from=YYYY-MM-DD&to=YYYY-MM-DD` | 查询相交区间（含两端，最长一年），返回 events、sources、sync_enabled      |
| `GET calendar/{id}`                          | 当前事件和全部修订版本                                                    |
| `GET calendar-snapshots/{id}`                | 下载核对时保存的官方 HTML 原始字节，以纯文本附件返回，需登录              |
| `POST calendar`                              | 补录有原文依据的事件，source 固定为 manual                                |
| `PUT calendar/{id}`                          | 修改 manual/fund 的日期、状态和条件，需提交当前 version；版本冲突返回 409 |
| `POST fund-drafts`                           | `{text,url}` 生成持久化草稿，尚不入历                                     |
| `GET fund-drafts`                            | 最近三十份未确认草稿                                                      |
| `GET fund-drafts/{id}`                       | 恢复指定草稿，包含原文与提取提示                                          |
| `POST fund-drafts/{id}/confirm`              | `{event,acknowledged:true}` 人工确认入历；重复提交返回原事件              |

事件结构定义在 `apps/server/internal/calendar/store.go`，客户端类型见 `apps/web/src/calendar.ts`。日期精度为 `date` 时 start/end 为 `YYYY-MM-DD`，区间包含结束日；为 `minute` 时为带偏移的 RFC3339，偏移必须匹配 timezone。状态支持 scheduled、confirmed、rescheduled、cancelled。开始/结束或时区变化会自动产生改期版本；取消优先于改期。重要性为 1–3。API 不允许编辑官方来源事件。

基金代码为六位字符串，草稿只提取明确标注的唯一代码和唯一完整日期区间；相对日期、多份额和多个区间需要人工填写。确认时使用服务器保存的原文及链接，客户端不能替换来源。原文上限 12000 UTF-8 字节。基金确认不调用模型；已开启自动提醒并关注该基金时，确认后的日历事件会进入提醒计划，草稿本身不会触发。

## 自动提醒

2026 年 11 月 1 日已部署并签收本轮发布，新增表、默认关闭状态及重启一致性检查通过；用户已确认电脑收到、小米锁屏显示及两端点击进入对应测试事项详情。六小时十五分钟运行与资源观察通过；实际发信时刻与观察窗口的重叠未单独核对，资源结论限于已采样负载，见 [实施状态](implementation-status.md)。

| 方法与路径                     | 用途                                                                                            |
| ------------------------------ | ----------------------------------------------------------------------------------------------- |
| `GET reminders`                | 设置、设备、最近 100 项单独关注设置、最近 30 条待发送计划及 30 条历史记录；不返回端点或回执凭据 |
| `PUT reminders/settings`       | 保存提醒总开关、设备 ID、日历类别、基金代码、提前时间和日期提醒选项，并原子重算队列             |
| `GET reminders/events/{id}`    | 事件有效关注状态、单独覆盖值、总开关、有效设备数及最多 12 条待发送计划                          |
| `PUT reminders/events/{id}`    | `{enabled:true/false}` 单独关注或关闭，优先于类别与基金代码规则                                 |
| `DELETE reminders/events/{id}` | 清除单独设置，恢复类别和基金代码规则                                                            |

设置字段见 `apps/web/src/reminders.ts` 的 `ReminderSettings`。默认 `enabled=false`，关注和设备列表为空。`early_hours=24`（0–168）与 `late_minutes=30`（0–1440），0 关闭该次提醒，相同时点合并；日期事件的 `date_previous`、`date_same` 默认开启，分别为原始民用日期前一天和当天的北京时间 09:00。`fund_end=true` 对有区间的基金增加最后一天及其前一天提醒，单日窗口不重复；不推算交易日或下一开放周期。

`kinds` 支持 macro、monetary、other，基金按六位 `fund_codes` 匹配。只有启用的所选设备接收消息。事件更新后十秒内重算待发送任务；认领发送时再次在事务内核对当前事件、关注和设备，并使用最新标题。改期、取消、暂停或取消关注撤销未发送的旧计划；推送服务已经接受的消息无法撤回。

同一事件、提醒时点及设备使用稳定任务 ID，文本修订不新增提醒，有限重试和进程重启沿用相同通知标签与回执凭据。新关注不补发已过时点，已有任务有效期最多十分钟，有具体时刻时不晚于事件开始。过期不补发；网络结果不确定时仍不能承诺严格一次送达。发送、服务接受、设备回执和点击分开记录，设备回执仅说明浏览器执行了显示流程。通知跳转为 `/finevent/#event=<ID>`，会话过期需先登录。

提醒表与既有 SQLite 共用事务，不新增后台服务；推送任务每秒认领一条，日历计划每十秒核对。记录沿用通知三十天清理，外键级联删除对应计划；已确认日历继续保留。版本回退会在旧程序启动前暂停自动提醒并撤销未发送任务，保留设置和历史，避免旧版误当作测试通知。重新升级后需要重新开启提醒。

官方来源每六小时独立同步一次；请求与文件大小有上限，所有解析结果先校验，再原子保存。失败记录原因并保留上次成功数据。来源条目消失不等同于取消，已保存记录不会因此删除；自动取消仅接受来源明确状态。没有来源 ID 的年度 HTML 日程以发布项目/年份/月份/位置标识，跨月移动或新增同月条目可能需要人工核对，不自动合并相似名称。

10 月 31 日补充来源版本已为日历单独设置 60 秒请求上限，快讯仍为 15 秒；单份正文上限为 2 MiB，父级取消仍有效。服务器首次发布共用了快讯客户端，统计局曾在 15 秒时截断，60 秒独立候选也曾超时，之后原版定时同步又成功；这些证据说明延长超时不能保证来源可用。候选与实际同步证据见 [实施状态](implementation-status.md)。

来源及当前适配范围：

- [国家统计局年度索引](https://www.stats.gov.cn/xxgk/sjfb/fbrcb/)：发现当年和已公布的次年日程，解析 CPI、PPI、PMI、国民经济运行情况，处理合并单元格与同月多次发布。
- [FOMC 日程](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm)：当年及未来会议日期区间，不推算决议、发布会或纪要时刻。
- [BLS 日历](https://www.bls.gov/schedule/news_release/bls.ics)：基于 UID 更新，处理 iCalendar 换行、时区、日期与取消；未支持的重复规则明确报错。开发网络及首次服务器同步均返回 403，尚未通过真实来源验收。
- [BEA 日程](https://www.bea.gov/news/schedule)：按发布主题及数据期匹配，保留官方时间并应用美国东部夏令时。
- [纽约联储日历](https://www.newyorkfed.org/research/calendars/nationalecon_cal)：独立的 `nyfed` 补充来源，按美国东部日期限定为当前月及下一已发布月份。首页若为当月，跟随实际“下一月”链接；若提前显示下月，跟随实际“上一月”链接取回当月，不扩展至下下月。只访问核验过的同站相邻月份链接并校验返回页月份，原始时刻按东部夏令时转换。未知标题、缺失时刻、过期或跨度异常的首页明确报错；提前切月时缺少当月链接也不接受部分导入。当前及下月整批校验后入库，任一页面失败均保留上次数据。保留纽约联储日程及 BLS 指标链接；它不是完整 BLS 日程，不清除 `bls` 错误，也不自动合并两源。月末修复已在生产成功导入 11 项，下一周期同步与长时观察已签收。

用户已接受统计局官方快照作为初始化补充：`-collect` 或独立 `-calendar-snapshot` 启动时校验随程序附带的原文及 SHA-256，仅填补缺少的 2026 年日程。已有记录（含取消）保持不变；若已有比核对时间更新的主源成功同步，跳过补入。同一快照只导入一次，不改写主源成功时间、计数、游标或错误。原始 HTML、采集/核对时间和摘要保存在 `calendar_snapshots`，不执行 HTML。

事件的可选 `provenance` 区分 `snapshot` 与 `supplement`；快照含 snapshot_id、retrieved_at、reviewed_at、sha256，补充来源含 authority_url。主源后续更新会移除当前事件的快照标记，旧版本仍保留。来源响应的 `snapshots` 分别给出导入条数、当前仍使用快照的条数及覆盖日期；这不同于来源成功计数。手工录入/基金确认不接受客户端伪造来源标记。

快照维护与后续改期限制见 [快照说明](../apps/server/internal/calendar/snapshots/README.md)。10 月 31 日修复版部署后，纽约联储即时重试成功，覆盖至 11 月 17 日；备份和重启检查通过，长时验收状态见 [实施状态](implementation-status.md)。统计局直接同步的 47 项已保留，旧快照未回填或覆盖。

月末修复升级针对“纽约联储当前页月份未更新，保留已有日程”、从未成功且条数为零的来源安排一次即时重试，无需再等六小时。`calendar_source_repairs` 持久记录原失败状态和请求时间，不清空同步游标；重启不会重复触发。其他故障和后续失败继续按六小时周期处理。发布验收等待这次请求结束后才检查重启一致性。此兼容路径的移除条件见 `apps/server/internal/calendar/repairs.go` 中的 TODO。
