# 来源健康与故障历史

已部署并完成本批签收，迁移、异常重启保全、双端页面、完整功能/资源观察及固定前两轮来源恢复检查通过。原始来源失败保留，范围与证据见 [实施状态](implementation-status.md)；此结论不代表上游持续无故障。入口为新闻“采集通道状态”和验证工作台“采集时效”，复用同一组件。不会开启 AI、改变关注设置、触发通知或修改 TrendRadar。

## 采样与保留

随每分钟 TrendRadar 导入读取当天、前一天数据库的 `crawl_records` 与 `crawl_source_status`。每天单独使用只读事务，不绕过 WAL；读取最多 10 秒，状态保存最多 5 秒。缺状态表、权限或超时错误独立记录，新闻导入继续。数据库不存在会显示日期覆盖提示；没有任一日数据库时记录读取失败。

以数据库日期、原始轮次 ID 和来源 ID 区分记录，采集时间按北京时间的原始分钟解析。同轮重复读取幂等，状态内容变化会更新当前快照，已观察到的异常独立保留。故障后再次成功并不删除原失败；同轮状态被修订时标注修订，不将它当作后续轮次恢复。

记录在 finevent 内保留 30 天，按采集时间由小时清理任务删除。第一次上线只回读两天，不自动扫描整个上游目录；超过两天的采样中断不能靠此次读取补齐。范围内未见失败不等于全程无缺口、所有配置来源均已接入或新闻完整覆盖。来源集合由已观察记录得出，首次从未上报的来源无法推断；停采也不能仅凭缺记录认定。部署前已有的报告仍按原有证据独立保留。

## JSON 接口

均为单用户登录后的只读 `GET /finevent/api/v1/` 接口，响应 `no-store`，匿名访问为 401。

| 路径                                   | 内容                                                                                |
| -------------------------------------- | ----------------------------------------------------------------------------------- |
| `news/source-health`                   | 服务时间、采样开关、状态读取成功/尝试/错误、最新轮次、当前保留记录起点及各来源状态  |
| `news/source-failures?source=&before=` | 来源可选，异常按轮次时间与稳定记录 ID 倒序，每页最多 30 条，`next` 用于加载更早记录 |

来源摘要包含 `id`、`state`、`last_attempt`、`last_status`、`last_success`、`last_failure`、`recovered_at` 和 `stale`。零时间表示尚无观察依据。状态为：

| `state`   | 含义                                                    |
| --------- | ------------------------------------------------------- |
| `healthy` | 最近轮次明确成功且来源和读取记录均新鲜，不证明完整覆盖  |
| `failed`  | 最近轮次明确失败；旧失败仍可能同时有 `stale=true`       |
| `missing` | 已观察过该来源，但最新全局轮次缺少它的状态              |
| `unknown` | 上游状态无法识别，或状态读取失败/过期，无法确认当前健康 |
| `stale`   | 最近来源记录成功，但距服务时间超过 40 分钟              |

状态读取超过 180 秒未成功或最新读取失败时，历史成功不能显示为当前健康。采集关闭时页面明确显示已有记录只供回看。来源失败、缺记录优先保留自身标签，过期原因在展开内容中同时显示。

故障历史每行包含 `id`、`source`、`at`、`status`、`recovered_at`、`corrected`。历史包括明确失败及未识别状态；缺少来源行只标为缺记录，不伪造失败。恢复时间为该来源在异常之后首次成功的采集轮次；并非精确停机时长或补采证明。`corrected=true` 表示上游后来修订或移除了同轮状态，最初异常继续可见。筛选或分页失败可重试，后台刷新不会重排历史、覆盖筛选或清除用户操作错误。

## 发布与验证

复用 `publish-news.ps1` 的备份、迁移、重启和 65 分钟资源/采集观察。新批次增加来源表与外键完整性、保留期内异常身份/内容、读取进度以及两项 API 的检查。正常清理边界内的旧异常不参与重启保全比较。首次同步可等待原有一分钟调度，观察开始三分钟后要求状态采样就绪；完整验收仍检查来源和资源，API 成功不表示所有上游来源成功。

本地回归覆盖跨日和 ID 重复、WAL 并发写入、状态修订与异常保留、缺表降级、过期/缺记录、分页、重启、清理和权限；浏览器检查覆盖桌面、393 px 窄屏、键盘焦点、筛选、分页、错误重试和后台刷新。生产验收需将真实故障记录与上游周期核对，再确认双端操作及资源增量。
